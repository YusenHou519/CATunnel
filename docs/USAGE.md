# CATunnel 使用手册

[返回 README](../README.md) · [English](USAGE.en.md) · [Agent 操作指南](../AGENTS.md)

CATunnel 在 Mac 与 Linux 服务器之间建立 SSH 反向隧道，让远端程序使用 Mac 上已有的 HTTP 代理。
它管理自己的 SSH 连接，不提供代理服务，也不修改 SSH、shell、编辑器或远端工具配置。
当前界面为中文；支持范围与实测结果见[验证记录](VALIDATION.md)。

## 下载安装

1. 从 [GitHub Releases](https://github.com/YusenHou519/CATunnel/releases) 下载预览包：
   Apple Silicon 选 `arm64`，Intel 选 `x86_64`。无需下载源码包或构建信息 JSON。
2. 解压 ZIP，将 `CATunnel.app` 拖入“应用程序”，再双击打开。
3. 点击菜单栏中的双向箭头圆形图标展开面板。应用不显示 Dock 图标，也不会自动弹出主窗口。
4. 首次启动为空列表；点击“使用引导”或“添加服务器”开始配置。

预览包使用 ad-hoc 签名，尚未经过 Developer ID 签名或 Apple 公证，目前适合开发者试用。
若系统提示无法验证开发者，或 Apple 无法检查 App 是否包含恶意软件，确认下载来源可信后，
可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)为此 App 单独允许打开：

1. 先双击 App，在拦截提示中选择“完成”或“取消”。
2. 打开 **系统设置 → 隐私与安全性**，在“安全性”中找到 CATunnel 被阻止的提示。
3. 点击 **仍要打开**，完成系统认证并再次选择“打开”。按钮文字可能因 macOS 版本而不同。

若没有该按钮，重新尝试打开 App 后再查看；受管理的 Mac 可能需要联系管理员。
无需关闭整个系统的 Gatekeeper。若提示“已损坏”“将损坏你的电脑”或检测到恶意软件，
请停止打开，记录完整提示、macOS 版本和包名并提交 Issue，不要将其当成普通未公证提示。

上述通用流程尚未在全新 Mac／账户、浏览器下载场景中完成实测。
构建、签名与 ZIP 校验通过不代表所有 Mac 均能成功打开；见[安装验证边界](VALIDATION.md#clean-configuration-versus-a-clean-mac)。

## 连接前准备

- **Mac：**部署目标为 macOS 13+；先启动可用的 HTTP 或兼容 HTTP 的 mixed 代理，监听 `127.0.0.1`。
  仅有 SOCKS 端口不能直接用于这里的 HTTP 代理检测。
- **服务器：**可访问的 Linux OpenSSH 服务；`ss` 用于检查监听端口，`curl` 用于网络检测。
  SSH 服务需允许反向端口转发；默认直连模式要求所选远端端口空闲。
- **认证：**已核实的主机指纹位于 `known_hosts`，使用默认密钥、可用的 SSH agent 或指定私钥。
  加密私钥需先在终端加载到 agent，供应用非交互认证使用。

CATunnel 使用 `-F /dev/null`，不读取 `~/.ssh/config`；请填写实际 IPv4 地址或可解析主机名，
不要填写仅在 SSH 配置中定义的别名。当前不支持跳板机／`ProxyJump`、交互式密码、IPv6 SSH 地址，
或应用内首次信任主机。最低系统目标不等于所有系统、架构均已实测。

## 添加和管理服务器

点击“添加服务器”或顶部 **+**，填写以下内容：

| 字段 | 含义 |
| --- | --- |
| 显示名称 | 面板页签中的名称，可用短名称便于切换 |
| 主机、SSH 用户、SSH 端口 | 实际 SSH 连接参数；SSH 端口默认 `22` |
| 本机代理端口 | Mac 上 HTTP/mixed 代理的端口，例如 `7890` |
| 服务器回环端口 | 远端程序使用的代理入口，例如 `17892`；不会开放到公网 |
| 私钥文件 | 可选；省略时使用默认密钥／SSH agent，仅保存文件路径 |

以上端口均为示例，需与你的实际环境一致；端口范围为 `1–65535`。
私钥路径支持绝对路径或 `~/`，所选文件须可读且权限仅限所有者（`600` 或 `400`）。
离线演示中的 `.example` 主机仅作占位，不能用于真实连接。

保存前点击 **检查连接准备**，应用会依次检查：

1. 本机代理端口是否接受 TCP 连接；端口可达尚不代表 HTTP 代理可用。
2. 所选密钥的文件属性与权限；不读取私钥内容。
3. 严格验证主机指纹的非交互 SSH 认证。
4. 远端是否具有 `ss` 和 `curl`。

此检查只执行只读依赖命令，不建立反向转发、不复用其他应用的控制连接、不访问外部网站。
修改表单或关闭编辑器会取消检查并清除旧结果。保存后需手动点击“连接”，保存本身不会连接。

未知或变化的主机指纹会阻止连接。可复制编辑器给出的终端验证命令，先独立核实服务器指纹，
再自行执行；该终端命令允许你交互确认信任，应用本身不会自动接受指纹或修改 `known_hosts`。
私钥口令、密钥内容均不存入 CATunnel。

连接或检测中的服务器须先停止才能编辑、删除；删除需确认，只移除本地条目。
其他服务器的连接不受影响，删除最后一项后恢复空列表。服务器较多时页签可横向滚动。
关闭面板会保留隧道，退出应用会停止它创建的连接；宽度与字号可在设置中调整。

## 固定入口模式（实验性，默认关闭）

当前源码在服务器编辑器的端口区提供“固定入口模式（实验性）”。旧配置和新建服务器
都默认关闭，关闭时仍使用原来的 SSH 反向转发。开关属于连接设置，只能在该服务器停止后
修改；保存不会立即连接，也不会安装远端程序。

对于已停止的服务器，可以点击 **“安装并启用”**。应用通过严格验证主机指纹的 SSH，
将随应用打包的程序安装到当前账号的 `~/.catunnel/fixed-entry/<端口>/` 私有目录，
在后台启动它，再通过另一条独立 SSH 请求确认程序持续运行。服务器需要 Python 3.9+；
此操作不使用 sudo，不下载依赖，也不修改 SSH、shell 或系统服务设置。

如果默认 `python3` 版本过低，可在 **“远端 Python 路径（可选）”** 中填写服务器上
已有 Python 3.9+ 可执行文件的绝对路径，例如 `/opt/tools/bin/python3`；这不是 Mac 上的路径。
留空继续使用 `python3`，不支持 `~/` 或 `conda activate` 等命令。安装、安装后验证以及
后续固定入口连接、续期和释放均使用同一选择，不修改系统 Python、PATH 或其他环境。
该输入在固定入口开关关闭时也可填写，以便先安装；未显式保存时不会改动现有配置。

成功后自动填入路径并打开**当前表单**的开关；仍需点击“保存”，然后手动连接。
失败、取消或关闭编辑器不会保存设置。取消仅停止本机等待，远端可能已经完成；
再次点击会检查并复用同版本程序。端口被占用、目录内有未知文件、版本不匹配或入口
正在被另一连接使用时会停止，不覆盖文件或结束其他进程。安装前也会拒绝与其他配置重复的入口。
此版本不配置开机自启；服务器重启后可再次点击，以启动状态干净的已有安装。

开启后填写“远端转接程序路径”和“远端私有运行目录”，都必须是服务器上的绝对路径。
服务器需预先运行兼容的 [relay.py](../experimental/fixed_entry/relay.py)，使用 Python 3.9+、
当前 SSH 账号所有且权限为 `0700` 的私有目录，并监听所填的“服务器代理端口”。
也可以自行部署并填写路径；普通保存、连接不会触发安装。已有默认密钥、SSH agent 和主机
指纹校验方式保持一致；Mac 侧实现为原生 Swift，不需要 Python。

远端转接程序持续持有入口；每次 SSH 连接申请不同的临时端口，通过通道和本地代理端口
健康验证后才接管入口。即使旧 SSH 会话还持有旧临时端口，也不需要先杀掉旧会话。
远端程序缺失、运行目录不安全或入口端口不匹配时会明确失败；端口不匹配不会申请接管。
“检查连接准备”仍只检查原有基础依赖，不能证明远端转接程序已就绪，连接时才验证它。

自动重连遵从该服务器已有选项；手动停止会关闭自有通道，并尽力只释放本次租约。
旧连接的迟到消息或唤醒重连不能抢回已被更新会话接管的入口。无法确认接管归属时会停止，
需要用户确认后手动重连。“端口占用时持续重试”只适用于默认直连模式，在此模式下隐藏且不生效。

固定入口存在不代表 Mac 休眠期间还能上网，正在进行的 TCP 请求也不能迁移到新通道。
用户目录安装可由上述按钮执行；服务监管和强制终止后的安全恢复仍需另行处理。此功能尚未宣称通过 Linux
实机或真实休眠验证。隔离模拟的运行方式见[实验说明](../experimental/fixed_entry/README.md)。

## 让远端程序使用隧道

建立连接后，复制面板显示的代理地址。例如远端端口为 `17892` 时：

```text
远端程序 → http://127.0.0.1:17892 → SSH 隧道 → Mac 127.0.0.1:7890 → 外网
```

先在**服务器终端**显式验证该代理；把端口改成自己的配置：

```bash
curl -q --silent --show-error --noproxy '' \
  --proxy http://127.0.0.1:17892 --connect-timeout 8 --max-time 20 \
  --output /dev/null --write-out 'HTTP %{http_code}\n' \
  https://www.google.com/generate_204
```

预期为 `HTTP 204`。该命令忽略 `.curlrc`，并明确使用指定代理，不修改任何配置文件。
需要测试 API 时可换成下一节端点；未认证的 HTTP 401 只证明网络可达，不证明登录或模型调用成功。

对于支持标准代理环境变量的程序，可仅给一次启动传入代理：

```bash
env HTTP_PROXY=http://127.0.0.1:17892 HTTPS_PROXY=http://127.0.0.1:17892 \
  http_proxy=http://127.0.0.1:17892 https_proxy=http://127.0.0.1:17892 your-command
```

将 `your-command` 换成实际命令；不同程序支持的变量与配置方式不同，需核对其文档。
若已有 `NO_PROXY`／`no_proxy` 规则，应检查目标服务是否被排除；按需要仅调整本次命令的环境。
也可在当前终端设置 `HTTP_PROXY`／`HTTPS_PROXY` 后启动程序；只影响该 shell 后续创建的子进程，
不会改变已有进程。后台服务需在获得授权后，按其实际启动方式设置环境并重启，再验证真实请求。
CATunnel 不会自动修改 `.codex`、`.claude` 或 shell 文件；连接成功与账号认证成功是两项验证。

## 登录启动、自动连接与自动重连

面板齿轮中的“设置”提供前两项；自动重连在服务器编辑器中设置：

| 设置 | 行为 |
| --- | --- |
| 登录时启动 | Mac 登录后打开 CATunnel，不决定连接哪台服务器 |
| 启动后自动连接 | 每台服务器独立选择；下次应用启动时生效，新建和旧配置默认关闭 |
| 意外断开后自动重连 | 恢复已经开启的连接；手动断开后不会自动拉回 |
| 端口占用时持续重试 | 当前源码新增，默认关闭；需开启自动重连，仅用于曾连接成功后的恢复 |

调整启动连接开关不会断开或重建当前隧道，服务器编辑器也提供此选项。
登录启动使用 macOS 登录项服务；需要批准时，设置页会提示并提供系统设置入口。
启用前请把 App 放在固定位置，通常为“应用程序”。

应用只读识别已知的旧 CATunnel 登录启动项；主动切换开关时才备份并处理已识别的旧项。
未知内容会保留并显示错误，仅打开设置不会迁移登录项。
登录启动与启动连接开关从 `v0.6.0-preview.2`（build 5）起包含在下载包中。
离线演示仅修改示例状态，不注册登录项、不保存日常配置、不连接服务器。

当前源码新增睡眠处理和持续恢复选项，尚未包含在上述下载包中。
收到系统睡眠通知时，CATunnel 关闭自己创建的 SSH 进程；唤醒后仅恢复睡前仍开启且启用了自动重连的服务器。
已手动停止、已终止重试或关闭自动重连的服务器保持停止。睡眠期间的连接请求仅在开启自动重连时排队等待唤醒，否则需唤醒后手动连接。
这不能保证服务器立即释放旧会话的监听端口，恢复速度仍取决于服务器和网络。

曾连接成功的隧道恢复时，如转发入口仍被占用，默认按 15、30、60、60、60 秒重试后停止。
开启“端口占用时持续重试”后，这 5 次用尽后继续每 60 秒重试，直到恢复或手动关闭隧道。
此设置在服务器编辑器中保存，下次连接生效；关闭自动重连时，该选项不可操作且不生效。
首次连接的端口冲突以及认证、主机密钥等错误不会因此持续重试。SSH 的转发拒绝提示可能也由服务器策略引起，仍需检查日志。

## 网络检测与数据

检测由用户主动触发，使用选定服务器的隧道：

| 检测 | 端点 | 结果含义 |
| --- | --- | --- |
| OpenAI API | `https://api.openai.com/v1/models` | HTTPS 可达；接受未认证的 401 |
| Claude 网络 | `https://claude.ai/cdn-cgi/trace` | HTTPS 可达及出口公网 IP |
| Claude API | `https://api.anthropic.com/v1/models` | HTTPS 可达；接受未认证的 401 |
| Google | `https://www.google.com/generate_204` | HTTPS 可达 |
| Net.Coffee 评分 | `https://ip.net.coffee/api/iprisk/{ip}` | Claude 出口 IP 的第三方风险信息 |
| Ping0 网页查询 | `https://ping0.cc/ip/{ip}` | 同一 Claude 出口 IP 的类型、风控值、共享人数估算 |

Net.Coffee 按服务器选择，**默认关闭**。开启后，下次主动检测会把出口公网 IP 提交给该服务。
关闭时 Claude 网络检测仍显示出口 IP，评分显示跳过，不请求 Net.Coffee。
应用不发送 API Key、Cookie 或模型提示词，无埋点或遥测；第三方检测失败不会停止已建立的隧道。
信任分**仅供参考**，不保证账号或模型可用；网段缓存会标注，不当成单个 IP 的实时结果。
Claude 网络检测不验证 Claude 网页的浏览器挑战，第三方端点也可能发生变化。

当前源码新增 **Ping0** 独立选项，默认关闭，尚未包含在 `v0.6.0-preview.2` 下载包中。
启用后，手动检测会向 Ping0 公开查询页发送已取得的 Claude 出口 IP，与 Net.Coffee 使用同一查询目标。
无需 API Key；只读取 HTML，不执行页面脚本或加载附加资源。没有后台定时查询。
Ping0 风控值越高风险越大，与 Net.Coffee 信任分方向不同，界面分别显示。
共享人数是过去 12 个月的估算区间，并非实时在线人数；网站未提供的项目显示“未提供”，不当成零。
Ping0 的“家庭宽带”分类也可能包含商业宽带或校园网，信息仅供参考。
网页结构变化、访问限制、无效响应或返回 IP 不一致时会显示查询失败，不绕过验证，也不影响现有隧道。
数据含义见 [Ping0 官方说明](https://ping0.cc/ip/faq)。

## 配置与日志

本地配置位于：

```text
~/Library/Application Support/CATunnel/profiles.json
~/Library/Application Support/CATunnel/ui-preferences.json
```

服务器文件格式为 `{"version": 1, "profiles": []}`。优先通过界面维护，修改前备份；
不要在应用运行时直接改写文件，以免与内存中的配置冲突。
兼容旧数组格式，仅在主动保存变更时升级；重复 ID 与冲突的服务器端口会被拒绝。
缺少 `identityFile` 时使用默认密钥／agent；缺少 `assessIPRisk`、`assessPing0`、`autoConnectOnLaunch` 或 `keepRetryingForwardingFailure` 时默认关闭。
`autoReconnect` 与 `autoConnectOnLaunch` 分别保存。

文件不可读、内容损坏或版本不受支持时，应用提示错误并阻止写入，保留原文件。
修复后重启应用重新加载；仅首次打开不会创建服务器配置文件。
应用标识为 `local.catunnel.CATunnel`，不导入其他应用设置；控制套接字位于私有临时目录，
最近日志与检测结果仅在内存中，不保存密码、私钥或 API 凭据。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 本地代理端口不可达 | 确认代理已运行、端口正确且支持 HTTP/mixed |
| 终端 SSH 可连，应用失败 | 检查终端是否依赖别名、跳板机或配置文件；核对实际主机、用户、端口与 agent |
| 主机密钥未知或变化 | 独立核实指纹后处理信任记录，不要关闭主机验证 |
| 密钥认证失败 | 检查密钥路径、权限、用户名和 agent；应用不弹出密码输入 |
| 远端端口占用或转发被拒绝 | 选择空闲回环端口，或请管理员核实 SSH 转发策略；不要停止不明进程 |
| 隧道已连但工具不能用 | 先用显式 `curl --proxy` 测试，再分别检查程序代理支持、登录状态与服务权限 |
| 睡眠后未恢复 | 确认 Mac、本地代理和网络已恢复，查看自动重连开关与日志；旧服务端会话可能仍占用端口，已停止的服务器不会自动连接 |
| 配置加载错误 | 保留并备份原文件，修复格式／版本后重启，不用空配置覆盖 |

提交 Issue 前请移除日志中的凭据与私人主机信息。构建、离线演示与测试入口见
[开发指南](../CONTRIBUTING.md)，代理使用与修改边界见 [Agent 操作指南](../AGENTS.md)。
